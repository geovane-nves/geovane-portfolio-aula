API Carrinho

Gerencie o carrinho de compras do seu e-commerce.

O Cart & Order Management API é um projeto backend desenvolvido para simular as principais operações de um e-commerce, permitindo o cadastro de usuários, o gerenciamento de produtos e carrinhos de compras e a criação de pedidos. A aplicação implementa regras de negócio como cálculo automático do valor total, controle de estoque e acompanhamento do status dos pedidos.

O sistema foi estruturado com base nos princípios de Domain-Driven Design (DDD) e nas boas práticas de desenvolvimento de APIs REST. Sua modelagem foi planejada utilizando diagramas UML, definindo as entidades e seus relacionamentos para organizar a lógica da aplicação de forma clara e consistente.

Sistema de Rifas

Compra e venda de rifas pela web.

O Raffle-System é um sistema de gerenciamento de rifas desenvolvido em Java com Spring Boot. A ideia é oferecer o backend completo para que uma plataforma de rifas funcione: usuários se cadastram e fazem login com autenticação, e quem organiza pode criar rifas e controlar os bilhetes (números) de cada uma. O projeto está organizado como uma aplicação Maven padrão, com pom.xml, wrapper mvnw e um arquivo .env.example para configurar as variáveis de ambiente.

Do lado de quem participa, o sistema cobre o fluxo de compra: o usuário escolhe bilhetes, realiza a compra e paga, com uma carteira (wallet) para gerenciar saldo. O sorteio é automatizado, ou seja, o sistema define o vencedor sem intervenção manual. O repositório ainda está em desenvolvimento

Sistema de Bibliotecas

Gerenciamento de acervo, empréstimos e usuários.

O Library flow API é uma API REST para gerenciar uma livraria digital, desenvolvida em Java 17+ com Spring Boot e PostgreSQL. Ela simula o ciclo completo de uma biblioteca: cadastro de livros e de várias cópias de cada título, aluguel e cálculo automático de multa por atraso, e um sistema de reservas para quando não há exemplares disponíveis. O projeto nasceu como um estudo avançado, com foco em boas práticas de arquitetura, segurança e persistência de dados.

Na parte técnica, a aplicação segue uma arquitetura em camadas (Controller, Service, Repository e DTOs), com JPA/Hibernate para acesso ao banco, validações com Bean Validation e tratamento centralizado de exceções. A segurança usa Spring Security com autenticação JWT, senhas criptografadas com BCrypt e autorização por papéis (ADMIN e USER).

Participei do desenvolvimento web do Educa Drones

Desenvolvimento

Um projeto real apresenta desafios diferentes daqueles encontrados em exemplos simples. É necessário considerar a organização dos arquivos, a consistência visual das páginas, a manutenção do código e a maneira como o conteúdo será atualizado ao longo do tempo.

No desenvolvimento do site, o uso do Django permite trabalhar com templates, views e recursos administrativos. Isso abre possibilidades para que informações, como notícias e conquistas, sejam gerenciadas de forma dinâmica, sem depender de alterações manuais no HTML a cada atualização.

Outro aprendizado importante é compreender que o desenvolvimento não termina quando uma página funciona. Testar, revisar e ajustar a interface também fazem parte da construção de uma aplicação confiável.

Essa experiência reforça a importância de desenvolver pensando não apenas em quem acessa o site, mas também em quem precisará mantê-lo e ampliá-lo no futuro.

Atrás de uma aplicação web

Web

Uma aplicação web pode parecer simples para quem a utiliza. Um formulário, uma tela de login ou uma lista de informações são elementos comuns, mas existe uma estrutura responsável por fazer tudo funcionar.

O front-end é a parte com a qual o usuário interage. É nele que encontramos os componentes visuais, os formulários, os botões e os elementos que tornam a navegação possível.

O back-end trabalha com as regras da aplicação. Ele recebe solicitações, valida informações, executa operações e determina como os dados devem ser processados. Em projetos com Java e Spring Boot, essa estrutura pode ser organizada em controladores, serviços e repositórios.

Já o banco de dados permite armazenar e consultar informações de maneira persistente. É nele que ficam os registros que precisam continuar disponíveis mesmo depois que o usuário fecha a página.

Por que planejar antes de programar?

Desenvolvimento

Quando surge uma ideia para um site, a primeira vontade costuma ser abrir o editor e começar a escrever HTML e CSS. Entretanto, dedicar algum tempo ao planejamento pode evitar retrabalho e tornar o desenvolvimento mais organizado.

O primeiro passo é entender o objetivo da página e o conteúdo que precisa ser apresentado. Depois, referências visuais e rascunhos ajudam a definir a distribuição dos elementos, a hierarquia das informações e o caminho que o usuário seguirá durante a navegação.

A organização em componentes também faz diferença. Separar elementos reutilizáveis permite manter uma estrutura mais clara e facilita alterações futuras. Em vez de concentrar toda a interface em um único arquivo, cada parte pode ter uma responsabilidade bem definida.

APIs REST: conectando diferentes partes de uma aplicação

APIs

Em muitas aplicações modernas, a interface e o servidor são desenvolvidos separadamente. Para que essas partes trabalhem juntas, é necessário estabelecer uma forma de comunicação. É nesse contexto que as APIs REST se tornam importantes.

Uma API disponibiliza operações que outros sistemas podem utilizar. Em uma aplicação de gerenciamento, por exemplo, podem existir endpoints para cadastrar usuários, consultar registros, atualizar informações e excluir dados.

O HTTP oferece métodos que ajudam a representar essas operações. O GET é utilizado para consultar recursos, o POST para criar ou processar informações, o PUT e o PATCH para atualizações e o DELETE para remoções.

O processo também faz parte do resultado

Desenvolvimento

Quando observamos um projeto finalizado, é fácil enxergar apenas o resultado: uma interface pronta, funcionalidades funcionando e uma estrutura aparentemente organizada. O caminho até esse ponto costuma ser bem menos linear.

Durante o desenvolvimento, surgem erros inesperados, comportamentos que não correspondem ao planejado e decisões que precisam ser revistas. Algumas soluções funcionam na primeira tentativa; outras exigem pesquisa, testes e várias modificações.

Aprendi a enxergar esses momentos como parte natural do processo. Um erro pode revelar uma falha de lógica, uma estrutura mal planejada ou simplesmente algo que ainda não compreendi completamente.
